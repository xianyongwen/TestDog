> 成片放 `doc/docs/public/videos/quick-start.mp4`，接线在 README.md / README.zh-CN.md / 文档首页（已接好）。
> 分镜按产品真实 UI 文案编写；节奏不必精确卡秒，剪辑时用变速/裁剪对齐节拍即可。

## 录前准备（checklist）

1. **启动 demo 服务器**（改版状态由它记忆，必须用它录，原因见「为什么必须用本地服务器」）：

   ```bash
   node doc/recording/quick-start/demo-server.mjs
   # 页面: http://localhost:4173/demo/order-admin/
   ```

2. **TestDog 里建好项目与用例**（打开软件前完成，镜头里不用拍建过程）：
   - 项目管理 →「新建项目」→ 项目名称 `汪汪商城演示`，**起始地址填 `http://localhost:4173/demo/order-admin/`**（录制页会自动预填这个地址）
   - 进入项目 →「新建用例」→ 用例标题 `订单发货流程`
3. **确认 demo 页处于 v1**：打开 `http://localhost:4173/demo/order-admin/`，右下角胶囊应显示「模拟改版 · 当前 v1」；若显示 v2，点一下切回（或重启 demo 服务器）。
4. **用例详情页确认「无头模式」开关关闭**（默认关闭），运行时浏览器可见，画面更有内容。
5. 普通浏览器另开一个 demo 页标签页备用（25-30s 拍「模拟改版」用）。
6. 录屏建议 1440×900 或 1280×800 逻辑分辨率、30fps 以上；标题卡页 `doc/recording/quick-start/title-card.html` 浏览器全屏（F11）另录。

**为什么必须用本地服务器录**：回放引擎会导航到**录制时记录的 URL**，而回放用的是全新浏览器实例（无共享存储）。demo 页的版本状态存放在本地 demo 服务器内存里，任何新开的页面加载都会读到当前版本——这样「点改版 → 回放必失败」的剧情才能稳定复现。若用部署后的线上静态页（softwing.top）录制，改版状态写进 URL 参数，回放时不会带上，剧情不成立。

## 录制与剪辑提示

- **15-20s 的三步操作**是全片关键，提前空手排练两遍：搜索 → 查询 → 发货，总耗时控制在 5 秒内。
- **30-40s 自愈段真实耗时不定**（取决于模型网关响应），成片里对这段 1.5x-2x 变速对齐节拍；确保画面里能看清紫色「自愈」标签和失败截图。
- **失败的呈现方式**：自愈开启时该次运行最终结果是「通过（带自愈标记）」——「测试失败」的瞬间表现为步骤 4 的长时间停顿（定位器在等一个已消失的元素）+ 随后亮起的紫色「自愈」标签；字幕在这段承载「测试失败 → AI 修复」叙事，30-35s 的停顿期是天然悬念镜头。
- **自愈给出的新定位器**：可能是语义形态（如 `getByRole('button', { name: '出库' })`），也可能回退为 xpath 形态——两者都属正常，均可「采纳」回写并通过重跑（验证时曾产出 xpath 形态并顺利通过）。
- **20-25s 的措辞**：录制导入是纯规则解析（不调 AI），字幕写「自动生成结构化测试用例」比「AI 自动生成」更准确；AI 只出现在 30-40s 自愈段。若坚持「AI 自动生成测试用例」的文案，建议把这句留给自愈段。
- demo 页数据是前端静态数组，**刷新即重置**——录砸了刷新页面就能重来（改版状态在服务器内存，重启 demo 服务器即回 v1）。
- 若自愈修复的定位不稳定（没找到「出库」按钮）：在脚本编辑器把步骤 3 的「说明」改成「点击该订单的发货按钮」再跑；自愈按步骤的自然语言指令重新定位，说明越明确越稳。

## 成片记录（2026-09-11 已交付 v1）

- **成片**：`doc/docs/public/videos/quick-start.mp4`（1920×1080，50 秒，无声，H.264 + faststart），由 Playwright 驱动真实产品 UI（Vite dev :1421 + 隔离后端 :4124 + dev.db 副本）逐拍录制后用 ffmpeg 合成；真实 AI 网关跑通了「改版失效 → 自愈 → 采纳 → 复跑通过」全链路（自愈耗时 16.3s 一段在成片中 3x 变速）。
- **唯一 reconstructed 环节**：15-20s「操作网页」。产品的录制浏览器是 codegen CLI 起的独立窗口，无法程序化驱动，因此该拍在等效浏览器中真实操作 demo 页录得画面，同时把等价的 codegen 脚本内容持续写入 codegen 输出文件，让真实导入管线解析出同样的 4 步——「停止并导入」后的步骤表、保存、后续运行与自愈全部是产品真实行为。
- **随片产品修复**：`runnerService.ts` 自愈指令回退——录制脚本只有 `description`（无 `instruction`），此前自愈条件要求 `instruction` 导致**手动录制的脚本永远不会触发自愈**（与 replay.md 文档承诺不符）；现回退到 `description`（即 codegen 操作行）作为自愈指令。
- 若要按本分镜自行重录更高规格的成片（真人鼠标、缩放动效），直接按上文分镜与 checklist 操作即可；demo 页与 demo server 的用法不变。
