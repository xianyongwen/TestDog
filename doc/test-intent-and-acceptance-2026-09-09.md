# 测试意图、强断言与生成完成校验

## 使用方式

在原有生成计划确认窗口中增加测试意图，不增加确认轮次：

- 场景：正向、负向或混合。
- 目标与前置条件。
- 数据约束：固定数据或允许生成的数据；值支持现有环境/系统变量。
- 验收目标：ID、业务结果、具体验证范围、验收依据、是否必验，以及断言类型/预期。
- 清理要求。

每个必验目标须关联一个计划断言，计划行中可以选择目标 ID。编辑验收类型和预期会同步对应计划断言。用户仍可调整路线；生成工具不能擅自改变已确认目标的断言类型和预期。

约定随脚本版本保存，可在用例详情查看，并随另存版本、导出和导入保留。已有脚本没有约定时继续兼容。数据库通过 Prisma 迁移文件及应用启动时的幂等迁移新增 `TestScript.intent`，无需手动改表。

## 断言语义

| 类型 | 含义 |
| --- | --- |
| visible / hidden | 唯一目标可见 / 隐藏或不存在；多匹配错误不视为隐藏 |
| text | 指定范围可见文本包含期望；旧脚本无定位器时继续使用 body |
| text_exact | 规范化空白后全文相等 |
| value | 表单字段值精确相等，允许空字符串 |
| checked / unchecked | 控件选中 / 未选中，控件不存在时失败 |
| enabled / disabled | 控件启用 / 禁用，控件不存在时失败 |
| count | 查询匹配节点的数量，包括隐藏节点；支持 0 |
| url / url_exact | URL 包含 / 精确相等 |

生成与回放共用 `waitForBrowserAssertion`，在超时预算内重试。`count` 和 `hidden` 可以使用稳定的定位描述符，不要求唯一命中，不接受快照临时编号。若指定父范围，父范围必须唯一存在，避免因父范围丢失而错误通过零数量断言。

断言失败不再调用 AI 重定位自愈，避免把真实缺陷变成通过；动作保留原有自愈。已有接口和 WebSocket 回放断言继续支持，本次没有新增生成期接口断言工具；预拆分只计划当前生成器支持的浏览器断言。

## 完成门槛与证据

1. `assert` 使用 `criterionId` 关联已确认目标，并校验类型/预期；非 URL 目标必须提供定位范围。
2. 只有真实断言执行成功、步骤保存后，宿主才登记通过证据。模型的总结或自行声明不能登记证据。
3. 证据签名绑定目标定义、当前断言及其前序执行步骤。修改定位、数据、顺序或删除相关步骤会使证据不再匹配；仅修改说明文字不影响执行证据。
4. `finish` 必须满足所有必验目标有有效证据且末步为断言。全局脚本审查之后再次校验，防止审查删除关键断言后仍放行。
5. 证据随暂停检查点保存。续跑使用保存的证据与当前保留脚本重新匹配；客户端不能通过编辑 `criterionId` 伪造通过。
6. 用户跳过必验项后可继续其余部分，但不能报告完整完成。

`read_coverage` 分页返回目标及覆盖状态；运行日志展示覆盖变化。意图随原有预拆分一次输出，覆盖校验不额外调用模型。初始意图有字符预算，工作记忆只保留紧凑覆盖状态，完整约定按需读取。

## 边界

- 门槛证明的是生成过程中，当前保留脚本对应的验收断言曾实际通过，不等于已经在全新环境中完整回放。
- 验收描述到真实元素的语义对应仍依赖生成器定位和用户审阅；宿主可以验证类型、预期、查询及证据一致性，不能仅凭自然语言确定业务含义。
- 固定数据、前置条件和清理要求进入结构化约定及生成提示；只有被列入验收目标的项目才受自动覆盖门槛约束。
- 老的暂停任务没有结构化意图时保留原完成规则；新生成必须输出有效意图，不静默降级。
- 本次不包含前端诊断工具、本地语义动作缓存、独立缺陷结论状态或业务系统上的真实模型效果基准测试。

## 验证

新增回归覆盖意图解析/确认、预期不可弱化、真实浏览器强断言、作用域丢失、证据失效/恢复、审查后再次校验、旧库幂等升级和脚本保存/导入兼容。另运行现有完整测试套件（排除需要外部模型的 `select-option-stagehand.test.ts`）以及前后端构建。
